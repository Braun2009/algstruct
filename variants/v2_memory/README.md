# v2_memory — 记忆长度作为配置项

## 改动

`Generator` 的 `MEMORY` 从类常量变成 `AlgebraConfig.memory`，并由它派生定律的刚度：

```text
v3 = 1 / (2 · memory · dt)          记忆长度（token） = 1 / (dt · 2·v3)
```

## 它说明了什么

定律的系数不只决定"模式"，也直接决定状态能记多久。原先 `v3 = softplus(0.5) = 0.974`
给出 `2v3 = 3.9`、`dt = 0.1`，即 **2.5 个 token** 的记忆。此时 `a_t` 是当前 token 的
逐点函数，`A_t` 几乎恒定，`Z_t ≈ Aᵗ` 成为位置计数器。

驱动与乘积之间的内容损失可以量化：

| 量 | 跨位置变化 | 跨样本变化 |
| --- | ---: | ---: |
| 驱动 `‖d‖` | 2.62 | 1.70 |
| 状态 `‖a‖` | 6.41 | 0.34 |
| 乘积 `‖Z‖` | 1.50 | 0.054 |

驱动在样本间差 170%，穿过状态剩 34%，到乘积只剩 5.4%。`‖[A₁, A₆₄]‖_F = 0.0086`。

在 `group_state`、`window=1` 上提高记忆后，准确率从随机升到 0.393（`flip 0.957`），
但 `nocompose` 同时升到 0.995——说明此时记忆走的是 `a` 自身的递推，而非乘积。
这一现象导致了 [v6_hom](../v6_hom/)。
